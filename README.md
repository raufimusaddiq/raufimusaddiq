## Engineering principles

`01` **Correctness before cleverness.**  
Probabilistic systems are useful for interpretation. Critical state transitions should still have explicit ownership.

`02` **Failure behavior is product behavior.**  
Retries, idempotency, recovery, and partial failure belong in the design.

`03` **Operate what you build.**  
Deployment, observability, and security boundaries should be visible while the architecture is still easy to change.
